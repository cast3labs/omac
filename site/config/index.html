omac.toml reference

Every setting lives in one file, ~/.config/omac/omac.toml. Omac writes it on first launch with a comment on each setting, and applies a change when you save it. omac default-spec prints the whole default file.

81 keys in 12 tables. Set means the default omac.toml sets the key; example means it shows the key commented out. For a key the default file sets, the example is the shipped value.

border_colorstring"theme"set"theme" = the current theme's accent (omac theme set …; #33ccff with none); a hex like "#33ccff" always wins
theme_chromebooleantruesetwith a theme set, the workspace bar takes its background/text from the theme too; false = accent only
warp_cursorbooleantruesetmove the pointer to the newly focused window
focus_follows_mousebooleantruesetthe focused display follows the pointer (Super+keys act where you look)
focus_follows_mouse_windowbooleanfalsesetalso let the focus BORDER follow the window under the pointer (opt-in; border-only — never activates the app or steals keyboard focus; yields while typing)
focus_follows_mouse_activatebooleanfalsesetthe third level, "type where you point": ALSO activate the app under the pointer (opt-in; needs both settings above, else inert — omac status says so). macOS activation raises the app's windows and swaps the menu bar, so it stands down for open menus (NOT popovers - they sit at the normal window level), sheets/modals on either app, text fields, the second after a keystroke, anything drawn over the tile, and a display in native full screen; dwindle workspaces only; exclude an app with [[rule]] follow_mouse = false. The menu-bar item's "Activate on hover" row edits THIS line, and turning it on there also turns on the two settings above, which it needs
focus_follows_mouse_activate_delay_msinteger250sethow long the pointer must rest on the SAME window before it is activated (100-5000). Longer than the border's 70 ms on purpose: reaching for the Dock or another display sweeps the pointer across windows
managed_displaysstring"all"set"all", "main", or display ids like "1,67" (see omac status)
managed_appsstring""set"" = every app, or bundle ids: "com.apple.TextEdit,com.apple.finder"
workspace_barbooleantrueseton-screen workspace strip per display; click a number to switch
strict_tilingbooleanfalsesetnever float; every window fills its tile (float rules ignored; toggle_float too unless allowed below). set here — no menu toggle
strict_tiling_allow_fullscreenbooleantrueset(only when strict_tiling) keep Super+Ctrl+F and Super+Alt+F (full width); false = always show the dwindle layout
strict_tiling_allow_floatbooleanfalseset(only when strict_tiling) let YOU float a window on purpose with Super+Shift+Space; rules/auto-float still never do, and a reload/Reorganize keeps only the floats you made
focus_yields_to_text_inputbooleanfalsesettrue = Super+arrow does native ⌘-arrow text motion in text fields; false (Omarchy) = it always moves window focus (use RIGHT ⌘ for text motion)
scroll_min_widthinteger500setscrolling layout (SUPER+SHIFT+L): min column width in px — a column never shrinks below this (Chrome's floor ~500)
scroll_peekinteger32setscrolling layout: px of the nearest off-view column that peeks at each edge (0 = no peek)
scroll_min_heightinteger300setscrolling layout: a window is stacked into a column only if every row keeps at least this many px
ocr_languagesarray of strings["en-US"]setOCR (Super+Ctrl+T): recognition languages in priority order, the analog of OMARCHY_OCR_LANGS. BCP-47 tags ("en-US", "fr-FR", "de-DE", "zh-Hans", "ja-JP"); tesseract codes ("eng", "chi_sim") are accepted too. An unusable entry is logged and skipped
ocr_keep_line_breaksbooleantruesetOCR: true keeps the recognised layout (an address stays four lines — tesseract's preserve_interword_spaces); false folds the selection into ONE line, for a phone number or an address you want in a single field
pin_reserves_spacebooleantruesetpin (Super+Shift+Ctrl+O) snaps the float to the edge whose band costs the LEAST TILING AREA and reserves that band: managed windows tile around it, so it stays visible whatever you focus. macOS has no honest always-on-top for another app's window. A float hugging no edge reserves nothing and stays put. Pop (Super+Ctrl+O) never reserves; false = no snap, no band

"system-default" (the macOS default app) counts only for browser and editor; elsewhere it is skipped
