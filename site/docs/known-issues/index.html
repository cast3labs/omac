Known issues

What does not work yet, or works differently from what Omarchy does, in Omac 1.0.1. Each item says what to do meanwhile. Something else broken? Open an issue with the output of omac status and what you pressed: https://github.com/cast3labs/omac/issues/new/choose

Updating from an earlier preview

  • Grant Accessibility again. From 1.0.0 Omac has a new identifier, com.cast3labs.omac, so macOS sees it as a new app. The preview's row in System Settings → Privacy & Security → Accessibility is also named Omac, may stay switched on, and does not count for the new app. If Left ⌘ shortcuts do nothing after the update: select the old Omac row and click −, then click +, add ~/Applications/Omac.app and turn it on. omac status must then show accessibility and tap both true. Do the same under Screen Recording, Microphone or Automation if you used them.
  • Coding agents ask once more. Approvals you gave a preview to launch a coding agent are not carried over: Omac asks again the first time you launch each one.
  • A preview cannot update itself. Install the new version over it once, the way you installed the preview; from then on, Check for Updates… in the Omac menu works. Your settings are kept.
  • The theme you are on shows its own pictures at the next theme switch or next background (Left ⌘ Ctrl ⌥ Space): Omac does not repaint the desktop by itself after an update.

Macs and macOS

  • Intel Macs are not supported. The installer stops on one. No plan to add them.
  • macOS 14 and 15 are allowed but not tested. Every test so far ran on macOS 26. Report what differs.
  • More than one external display on an M1 Air needs DisplayLink. The Mac drives one external natively; the multi-display tests used DisplayLink adapters, which macOS treats a little differently (no native full screen on those displays).
  • Stage Manager has not been tested with Omac.

Windows

  • "Pin" is not a true always-on-top. macOS lets only the active app's windows sit on top, and the private way around that was measured to do nothing. A pinned floating window instead reserves a band at a display edge, and Omac tiles the other windows around it. An app Omac does not manage, a native full-screen Space, or a window you drag by hand can still cover it.
  • Native full screen is macOS's own Space. Omac keeps track of it and puts the window back when it leaves, but does not tile inside it. Use Left ⌘ ⌥ F (full width: fills the usable area) for a tiled "big" window, Left ⌘ Ctrl F for native full screen.
  • A window that refuses its frame floats in place. Some apps set a minimum size larger than their tile (Chrome about 500 px wide, Finder's sidebar layouts, small utility panels). Omac floats such a window where it is; on a second refusal it leaves it unmanaged. Give the tile more room, or float it on purpose with Left ⌘ Shift Space.
  • Hidden workspaces park windows as a 1-pixel sliver at the nearest screen edge (macOS has no way to hide a window without minimising it). They still show in Mission Control and in the app switcher. Quitting Omac puts every window back.
  • Dragging a tiled window with the mouse does not swap it: Omac puts it back in its tile. Move tiles with the keys (Left ⌘ Shift ←, and the other arrows), or float the window first.
  • The layout survives an Omac restart only while the apps keep running (state kept 12 hours). Windows opened while Omac was not running are tiled fresh.
  • Two copies of Omac conflict. An older copy in /Applications and the current one in ~/Applications fight over the keys. omac status lists any other copy under other_copies; the one-line installer removes the /Applications copy for you.
  • An app that stops answering is left out for a while. Omac stops asking it where its windows are for 5 seconds, then up to 30, so a new window of it may wait to be tiled until it answers. omac status lists such apps under quarantined_pids.

Keys

  • Some Omarchy chords are moved, because macOS or common apps own them: full screen is Left ⌘ Ctrl F, macOS's own, where Omarchy has its tiled full screen (⌘F is Find; full width stays Left ⌘ ⌥ F); the theme's next wallpaper is Left ⌘ Ctrl ⌥ Space (⌃⌘Space is the emoji picker); column stacking is Left ⌘ Shift Ctrl ←/→ (⌘⌥←/→ switches Chrome tabs); text capture is Left ⌘ Ctrl T (Macs have no Print Screen); dictation is held with left Ctrl and fn (no F9 hold on a Mac keyboard). What each key does: https://omac.ghostype.ca/features/ (Left ⌘ K shows every key Omac binds).
  • Omac's key is always Left ⌘: there is no choice of another key yet. A browser's number keys for its tabs work with Right ⌘.
  • Left ⌘ Space stays Spotlight (or Raycast): Omac has no launcher of its own on purpose.
  • ⌥Esc reads the selection aloud only when Omac's read-aloud is on; off, macOS's own "Speak selection" answers it. It ships off: turn it on with Read aloud in Omac's Speech menu.
  • Right ⌘ keeps the Mac's ⌘ shortcuts, including zoom: only Left ⌘ is Omac's Super.
  • Shortcuts stop while Secure Input is on (a password field, or a terminal's Secure Keyboard Entry): macOS keeps keys from every other app. omac status shows secure_input true and names the app holding it when macOS reports it.

Themes

  • The wallpaper is painted on the desktop each display shows. macOS keeps a picture for every desktop of every display; a desktop no display is showing keeps its older picture until you go to it. A picture you chose yourself in System Settings, and "Show on all Spaces", are left as they are. With "Displays have separate Spaces" off in Mission Control, only the main display is checked.
  • A theme switch made from a full-screen app paints that display's desktop when you leave full screen.
  • Chrome and Brave take a theme's frame colour on their next launch, not live (it is set as a managed policy, and only once you ran omac theme adopt).
  • omac theme off restores the wallpaper, not light/dark mode and not the colour files it wrote into other apps' folders (they are listed in the privacy policy; delete them by hand).
  • The screensaver starts on its key only (Left ⌘ Ctrl ⌥ S), not when the Mac is idle.

Speech

  • Dictation needs macOS 26 (Apple's on-device transcriber). On macOS 14 and 15 the dictation row is greyed with the reason.
  • The read-aloud voices are macOS's: a voice you have not downloaded in System Settings → Accessibility → Spoken Content is not available. Dictation's languages are macOS's too: omac speech asr list shows which ones are installed.

Updates and Homebrew

  • A copy installed with Homebrew updates itself too, as a downloaded one does: Check for Updates… in the Omac menu. After a Homebrew upgrade, the old version keeps running until you quit Omac and open it again.
  • Homebrew copies installed from the tap's old name (evanscastonguay/tap, before 2026-09-30) update as the README's Update says: Homebrew follows the moved tap on its next update. Until such a copy has been updated once, Homebrew refuses the new name to uninstall it: use brew uninstall --cask evanscastonguay/tap/omac.
  • The privacy policy is on the website, https://omac.ghostype.ca/privacy/ (and in French, /privacy/fr/); Privacy › Privacy policy… in the Omac menu opens it. An earlier preview carries its own copy inside the app.
