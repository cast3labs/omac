Politique de confidentialité d'Omac

Version : 2, 2026-10-08; approuvée par le mainteneur le 2026-10-08. Les versions et ébauches qui l'ont précédée sont énumérées sous « Modifications de cette politique ». S'applique à : l'application Omac et son outil en ligne de commande omac, au serveur d'Omac t.ghostype.ca et au site Web omac.ghostype.ca. English version: PRIVACY.md. Les deux disent la même chose.

En bref

  • Omac n'envoie rien à moins que vous le lui demandiez. Seules deux fonctions peuvent envoyer quelque chose d'elles-mêmes, et les deux restent désactivées tant que vous ne cochez pas leur case : un décompte d'utilisation quotidien et des vérifications de mises à jour automatiques.
  • Le décompte d'utilisation quotidien est un petit message par jour : la version d'Omac, la version de macOS, le nombre d'écrans et deux indicateurs oui/non. Il ne contient aucun identifiant. Le serveur d'Omac ne lit ni ne conserve jamais votre adresse IP. Cloudflare, qui exploite ce serveur, voit l'adresse afin d'acheminer le message; ce que Cloudflare conserve est décrit plus bas.
  • Une vérification de mises à jour demande à GitHub, qui héberge le site Web et les téléchargements d'Omac, s'il existe une version plus récente.
  • Tout le reste demeure sur votre Mac : vos réglages, la disposition de vos fenêtres, votre historique du presse-papiers et les fichiers dont Omac a besoin pour fonctionner.
  • Omac ne vend aucune donnée, n'affiche aucune publicité et ne crée aucun profil.
  • Les versions préliminaires antérieures d'Omac n'envoient jamais le décompte quotidien et ne vérifient jamais les mises à jour. La première version qui le peut est 1.0.0.
  • Les achats et les licences ne sont pas encore couverts. Rien n'est encore vendu, et aucune version d'Omac ne recueille de données d'achat ou de licence.
  • Questions : omac@ghostype.ca.

Qui est responsable

Omac est conçu par cast3labs, au Québec, Canada. cast3labs décide de ce qu'Omac recueille et pourquoi (le « responsable du traitement », selon le RGPD européen). Le responsable de la protection des renseignements personnels d'Omac au sens de la loi québécoise sur la protection des renseignements personnels dans le secteur privé (Loi 25, article 3.1) est le mainteneur, la personne qui dirige cast3labs, que vous pouvez joindre à omac@ghostype.ca.

Contact : omac@ghostype.ca. Écrivez à cette adresse pour toute question sur cette politique, y compris pour obtenir de l'aide afin de comprendre ce que signifie une case avant de la cocher. Le courriel envoyé à cette adresse passe par Cloudflare Email Routing, qui le transfère à la boîte aux lettres du mainteneur. Cette boîte est un compte Gmail, exploité par Google LLC aux États-Unis. Cloudflare garde un journal de chaque message qu'il transfère (son expéditeur, son destinataire, son heure d'arrivée et s'il a été livré), que le mainteneur peut consulter pendant 30 jours au plus.

Le décompte d'utilisation quotidien (facultatif)

Désactivé à moins que vous ne cochiez sa case. Omac pose la question une seule fois, dans sa première fenêtre, dans une case distincte, séparée de la question sur les mises à jour. Laisser la case décochée vaut un non, et Omac ne repose pas la question. Si vous quittez Omac pendant que cette fenêtre est ouverte, ou si Omac ne peut pas enregistrer votre réponse dans omac.toml, rien n'est enregistré ni envoyé, et la fenêtre repose la question à un lancement ultérieur, une fois qu'Omac peut enregistrer la réponse. Omac écrit chaque réponse avec consent_version, la version du texte de la case auquel vous avez répondu. Un oui sans lui, ou avec un numéro plus ancien, ne compte pas comme une réponse : c'est le cas d'un oui donné dans une version préliminaire antérieure d'Omac, dont la ligne du menu disait que le décompte n'était pas encore actif, et d'une ligne tapée à la main. Rien n'est envoyé pour ce oui, et la fenêtre repose la question, case décochée. Vous pouvez changer votre réponse en tout temps dans le menu d'Omac (« Share anonymous daily count ») ou dans votre fichier de réglages, ~/.config/omac/omac.toml :

[privacy]
daily_ping = true    # false, ou aucune ligne, n'envoie rien
consent_version = 2  # écrit par Omac avec votre réponse; un true sans lui n'envoie rien

À quoi il sert : compter combien de Mac utilisent Omac, avec quelles versions d'Omac et de macOS, et avec combien d'écrans, afin que le mainteneur sache quoi prendre en charge. Il ne sert à rien d'autre.

Ce qui est envoyé

Au plus un message HTTPS réussi par jour (voir « Quand »), exactement comme cet exemple. Les valeurs changent; les clés, jamais.

{"displays":"2","first_ever":false,"first_this_month":false,"os":"26.1","schema":1,"version":"1.0.0"}
Clé Ce que c'est Valeurs possibles
schema le format du message 1
version la version d'Omac une version comme 1.0.0; toute autre valeur est envoyée comme unknown
os la version de macOS, les deux premiers nombres seulement comme 26.1; le troisième nombre n'est jamais envoyé
displays le nombre d'écrans branchés 1, 2, 3, 4 ou 5+
first_this_month c'est le premier message du Mac ce mois civil (UTC) true ou false
first_ever c'est le premier message depuis l'activation du décompte true ou false

Il ne contient jamais aucun des éléments suivants : un identifiant, vos frappes au clavier, les titres de fenêtres, les noms d'applications, les noms ou le contenu de vos fichiers, votre nom, votre identifiant Apple, votre langue, votre emplacement. Les messages n'ont aucune clé commune, de sorte que le serveur ne peut pas savoir lesquels viennent du même Mac. Une limite : une configuration inhabituelle (une combinaison rare de versions et de nombre d'écrans) peut faire ressortir les messages d'un Mac tant que les messages bruts sont conservés (voir « Ce qui est conservé »).

Si vous désactivez puis réactivez le décompte, votre prochain message indique de nouveau first_ever: true et first_this_month: true; les chiffres publics peuvent donc compter la même installation plus d'une fois.

La requête porte aussi des en-têtes fixes qui ne disent rien sur vous : User-Agent: Omac/<version> (la même version que dans le message), Content-Type: application/json et Accept-Language: en (fixé, pour que votre liste de langues ne soit pas envoyée). macOS ajoute les en-têtes standard Host, Content-Length, Connection, Accept et Accept-Encoding. La requête ne porte aucun témoin (cookie), et rien d'elle n'est mis en cache.

Quand

  • Au plus un message réussi par jour, compté en UTC.
  • Le premier message après l'activation du décompte part le jour UTC suivant, jamais le jour même de l'activation.
  • Jamais avant un délai aléatoire de 5 à 60 minutes après le démarrage d'Omac ou la sortie de veille de votre Mac, pour que l'heure d'un message ne dise qu'à une heure près quand vous vous êtes installé devant l'écran.
  • Un message que le serveur refuse est réessayé plus tard : après 10 minutes, puis deux fois plus longtemps chaque fois, jusqu'à 6 heures d'écart. Quand le serveur demande à Omac d'attendre plus longtemps (une réponse HTTP 429 avec un en-tête Retry-After en secondes), Omac attend le temps demandé, jusqu'à 24 heures. Un Mac éteint pendant une semaine envoie un seul message à son retour, pas sept.
  • Un message qui ne reçoit aucune réponse du serveur, par exemple parce que votre Mac est hors ligne ou que la connexion est coupée, compte comme le message de ce jour-là, puisqu'il a pu arriver : le suivant part le jour UTC suivant.
  • Seule une version publiée d'Omac, signée par le mainteneur, peut l'envoyer. Une copie compilée à partir du code source ne l'envoie jamais.
  • Juste avant chaque envoi, Omac relit omac.toml et n'envoie rien s'il n'indique plus daily_ping = true.

Qui le reçoit, et ce qu'il voit

Le message va à https://t.ghostype.ca/v1/ping : un petit serveur (un Worker Cloudflare avec une base de données Cloudflare D1) que Cloudflare exploite pour le mainteneur.

  • Votre adresse IP parvient à Cloudflare avec chaque message, comme pour toute connexion. Cloudflare voit aussi les en-têtes ci-dessus et les détails techniques de la connexion chiffrée.
  • Le code du serveur d'Omac ne lit jamais ni votre adresse IP, ni aucun en-tête, ni l'emplacement que Cloudflare joint à chaque requête, et il n'écrit aucun journal. Les journaux de requêtes du serveur (Workers Logs) et leur exportation (Logpush) sont désactivés. Un test du 2026-09-27 a montré que, ces journaux désactivés, les journaux du Worker ne gardent aucune trace d'une requête.
  • Ce que Cloudflare fait lui-même échappe au contrôle d'Omac. Les outils de sécurité de Cloudflare montrent au titulaire du compte des échantillons des requêtes récentes, et de celles que ses règles ont bloquées ou limitées, avec leur adresse IP, jusqu'à 31 jours sur le forfait gratuit qu'utilise Omac. Une règle de limitation du débit qui protège le serveur compte les requêtes par adresse IP. Une deuxième règle refuse un message dont le User-Agent ne nomme pas Omac. L'outil de journal en direct de Cloudflare peut montrer les requêtes à leur arrivée; le mainteneur ne le laisse pas tourner et n'enregistre jamais ce qu'il affiche. Cloudflare décrit son propre traitement des adresses IP dans sa politique de confidentialité : https://www.cloudflare.com/fr-fr/privacypolicy/.

Ce que montrent les statistiques publiques

Les totaux sont publics à https://t.ghostype.ca/stats et https://t.ghostype.ca/stats.json : les installations ayant accepté le décompte, par jour et, pour chaque mois civil une fois terminé, par mois; pour le plus récent de ces mois, leurs versions d'Omac, leurs versions de macOS et leur nombre d'écrans, chaque installation comptée une fois, mais une installation qui a désactivé puis réactivé le décompte ce mois-là peut être comptée plus d'une fois; et le nombre de téléchargements. Tout nombre d'installations par jour ou par mois inférieur à 5 s'affiche comme <5, zéro compris. Dans les tableaux, une version d'Omac, une version de macOS ou un nombre d'écrans que partagent moins de 5 installations est compté sous « other », et « other » n'est jamais inférieur à 5 : tant qu'il le serait, même à 0, il prend aussi la plus petite valeur nommée; chaque nombre d'un tableau vaut donc 5 ou plus. Un mois n'est affiché qu'une fois terminé, et ses nombres ne changent plus ensuite. Les nombres de téléchargements, qui comptent des fichiers et non des personnes, s'affichent même lorsqu'ils sont inférieurs à 5. Rien sur la page ne décrit une personne.

Ouvrir la page montre à Cloudflare votre adresse IP et ce que votre navigateur envoie avec toute requête, comme son nom et vos langues préférées (voir « Qui le reçoit, et ce qu'il voit » pour ce que Cloudflare conserve); le code du serveur d'Omac n'en lit rien, et la page ne dépose aucun témoin et ne charge rien de personne d'autre.

N'importe qui peut envoyer un message qui ressemble à celui d'Omac, et le serveur ne peut pas le distinguer d'un vrai; les nombres peuvent donc inclure des faux. Qui envoie des faux sait combien il en a envoyé; pour lui, un nombre inférieur à 5 n'est donc pas caché : il pourrait apprendre combien d'installations ont envoyé un décompte un jour donné, si une installation à la configuration inhabituelle était active un mois donné, et même si son premier décompte de ce mois est arrivé un jour qu'il choisit; jamais laquelle, ni rien d'elle au-delà des valeurs que portent ses messages et des jours où ils sont arrivés.

Comment le désactiver

N'importe laquelle de ces actions arrête le décompte immédiatement :

  • dans le menu d'Omac, décochez « Share anonymous daily count »;
  • lancez omac telemetry off;
  • mettez daily_ping = false dans la table [privacy] de ~/.config/omac/omac.toml.

Omac efface telemetry.json dès qu'il lit un omac.toml qui dit non. Si Omac ne peut pas enregistrer omac.toml, il vous le dit, et le décompte reprend la prochaine fois qu'Omac lit le oui du fichier; telemetry.json reste jusque-là, pour que cette reprise n'envoie pas un deuxième message le même jour.

omac status affiche votre réponse (telemetry : not-asked, on ou off) et le jour du dernier message (telemetry_last_sent). Omac fonctionne de la même façon, que le décompte soit activé ou non.

Les vérifications de mises à jour (facultatives)

Désactivées à moins que vous ne cochiez leur case, qui est distincte de celle du décompte quotidien. Changez-la en tout temps dans le menu d'Omac, ou avec check_updates dans la table [privacy] de omac.toml. Comme pour le décompte, un oui sans le consent_version qu'Omac écrit avec chaque réponse (une ligne tapée à la main avant la version 1.0.0) ne compte pas comme une réponse : Omac ne vérifie pas, et la fenêtre repose la question.

À quoi elles servent : vous dire quand une version plus récente d'Omac existe. Omac utilise Sparkle, un module de mise à jour à code source ouvert très répandu pour les applications Mac.

Ce qu'envoie une vérification de mises à jour

  • Quand : au plus une fois par jour, et seulement tant que check_updates = true. « Check for Updates… » dans le menu d'Omac vérifie une fois, quand vous le choisissez, que la case soit cochée ou non.
  • Quoi : une requête pour la liste des versions à https://omac.ghostype.ca/appcast.xml. Comme toute requête Web, elle transmet votre adresse IP, et elle indique les versions d'Omac et de Sparkle. Son en-tête Accept-Language est fixé à en, comme celui du décompte quotidien, pour que votre liste de langues ne soit pas envoyée. Elle n'envoie aucune description de votre Mac (le « profil du système » de Sparkle est désactivé) et aucun identifiant.
  • Rien n'est téléchargé ni installé tant que vous ne choisissez pas d'installer une mise à jour. La mise à jour est alors téléchargée depuis GitHub, et Omac vérifie ses signatures avant de l'installer.
  • Une copie compilée à partir du code source ne vérifie jamais, pas plus qu'une copie lancée depuis un dossier de Nix ou MacPorts : Nix ou MacPorts la met à jour. Omac reconnaît une telle copie à son dossier ou, pour Nix, à la date que Nix donne à ses fichiers; une copie qu'il ne reconnaît pas est traitée comme une copie téléchargée, et vérifie tant que la case est cochée. Une copie téléchargée que macOS lance depuis un emplacement temporaire, avant que vous la déplaciez dans votre dossier Applications, ne vérifie pas tant que vous ne la déplacez pas. Une copie installée avec Homebrew vérifie, comme une copie téléchargée, tant que la case est cochée. Le dossier ne change rien au décompte quotidien : une copie ne l'envoie que si c'est une version publiée et que sa propre case est cochée.

Qui la reçoit

GitHub, qui héberge omac.ghostype.ca (sur GitHub Pages) et les téléchargements d'Omac, aux États-Unis. GitHub journalise l'adresse IP de chaque visite d'un site GitHub Pages pour des raisons de sécurité, et compte combien de fois chaque fichier publié est téléchargé (ces comptes sont des nombres publics). Le mainteneur ne reçoit aucun journal des visiteurs de GitHub Pages; il ne peut donc pas savoir qui a vérifié. GitHub décrit son propre traitement dans sa déclaration de confidentialité : https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement.

Sur votre Mac, Sparkle garde quelques renseignements dans les préférences macOS d'Omac : le moment de sa dernière vérification, une version que vous avez choisi d'ignorer, le fait qu'il a déjà été lancé, la position de sa fenêtre de mise à jour à l'écran, et un nombre aléatoire, jamais envoyé, qui décide quand une version publiée graduellement parvient à votre Mac.

À savoir aussi :

  • Frappes au clavier. Pour reconnaître ses raccourcis, Omac surveille le clavier; c'est pourquoi il a besoin de l'autorisation Accessibilité. Il n'enregistre ni n'envoie ce que vous tapez. Son journal nomme seulement un raccourci d'Omac quand il se déclenche.
  • Autorisations. En plus d'Accessibilité, Omac demande le Microphone seulement pour la dictée (il n'écoute que pendant la dictée : pendant que vous maintenez les touches de dictée, ou d'un appui sur la touche de bascule au suivant, une minute au plus sauf si vous changez cela dans omac.toml), l'Enregistrement de l'écran seulement pour lire du texte à l'écran, l'Automatisation pour ouvrir un terminal (pour un agent de programmation, ou avec « Finish in Terminal » quand Homebrew n'a pas pu terminer une installation) et pour faire passer macOS du mode clair au mode sombre, et les Notifications pour vos rappels et pour les courts avis d'Omac (sur le texte lu à l'écran, la dictée, la lecture à voix haute, les thèmes, sa première fenêtre et les vérifications de mises à jour).
  • Autres applications. Quand vous choisissez un thème, Omac écrit des fichiers de couleurs pour les applications que vous avez installées (comme Ghostty, Claude Code, opencode, Sublime Text, VS Code et iTerm2), change le fond d'écran et fait passer macOS du mode clair au mode sombre. Il ne modifie les réglages propres à une autre application qu'après omac theme adopt <app>, sauf le réglage de couleur de Chrome et de Brave, qu'un changement de thème met aussi à jour quand un tel réglage existe déjà. omac theme off remet le fond d'écran en place et retire le dossier de thème propre à Omac (~/.local/state/omac/current/); il laisse le reste tel quel :
  • macOS reste en mode clair ou sombre (changez-le dans Réglages Système, Apparence);
  • les fichiers de couleurs qu'Omac a écrits dans les dossiers d'autres applications restent, comme ~/.claude/themes/omac.json, DynamicProfiles/omac.json d'iTerm2, Omac.sublime-color-scheme de Sublime Text et ~/.vscode/extensions/omac-theme de VS Code; supprimez-les pour les retirer;
  • le réglage de couleur de Chrome et de Brave reste; cette commande le retire pour Chrome (pour Brave, utilisez com.brave.Browser) : defaults delete com.google.Chrome BrowserThemeColor;
  • les réglages d'une application adoptée restent tels quels jusqu'à ce que vous les changiez dans cette application.
  • L'ouverture à la connexion est inscrite dans les éléments de connexion de macOS. Une première installation avec le programme d'installation en une ligne l'active; une mise à jour laisse votre choix tel quel. omac login off, ou « Launch at login » dans le menu d'Omac, la désactive, et omac login on la réactive.
  • Le programme d'installation met Omac dans ~/Applications/Omac.app et la commande omac dans ~/.local/bin, peut ajouter deux lignes marquées au fichier de démarrage de votre shell pour que la commande soit trouvée et, lors d'une première installation, active l'ouverture à la connexion (plus haut).
